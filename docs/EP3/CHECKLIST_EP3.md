## Pendientes que no se presentan como demostrados

| Requisito o riesgo | Estado | Motivo |
|---|---|---|
| Productor y consumidor como despliegues de negocio separados | Pendiente | Ambos están dentro de CarniveroCrud |
| Compra/checkout de extremo a extremo con MySQL y Azure reales | Pendiente | Tests locales H2/JWKS y mensajería aislada no sustituyen este flujo |
| Entrega SMTP real a una cuenta autorizada | Pendiente | Correo y fallos SMTP simulados; no se utilizó Gmail real |
| Reinicio de todo el backend y del broker | Pendiente | Se probó reinicio del consumidor dentro del contexto aislado |
| Prevención garantizada de correos duplicados y recuperación de publicación | Pendiente | Redelivery y fallos posteriores al commit siguen siendo riesgos |
| Timeouts SMTP explícitos | Pendiente | No configurados en las fases implementadas |
| API administrativa autenticada para acceso remoto | Pendiente | API actual sin JWT y limitada a loopback |
| Despliegue y validación AWS | Pendiente | No ejecutados; FASE 9 no iniciada |

La limitación arquitectónica debe explicarse en la entrega y contrastarse con el docente. Las recomendaciones previas a AWS están en el [README EP3](README_EP3.md); no constituyen autorización ni evidencia de despliegue.
